fix(l5): L5 entity/relation write fully broken — SourceType enum mismatch + stale embedder sidecar call

## Root Causes

1. **Kuzu entity write:** `SourceType.L5_DIGEST` does not exist in the installed
   `hy_memory.models.memory` SDK — only `EXPLICIT`, `INFERRED`, `COMPOSITE` are
   defined. Every `MemoryNode(source_type=SourceType.L5_DIGEST, ...)` raised
   `AttributeError`, causing all entity writes to fail silently with the warning:
   ```
   [L5] could not write entity <name>: L5_DIGEST
   ```

2. **Qdrant entity embed:** `_embed_entities_to_qdrant` called the deprecated
   embedder sidecar on `http://127.0.0.1:19528/v1/embeddings`, which no longer
   runs after `apply_inprocess_embed_patch` (patch #3) eliminated it. Every embed
   attempt failed with:
   ```
   [L5] entity embedding failed: HTTPConnectionPool(host='127.0.0.1', port=19528):
   Max retries exceeded ... [WinError 10061] No connection could be made
   ```

**Result:** L5/L6/L7 stayed at 0 despite `l5_inprocess: True` and S2 digests
firing. The L5 extraction ran, but zero entities/relations reached Kuzu or Qdrant.

## Changes

- **`src/hyatlas_memory/l5_inprocess.py`** (line 387):  
  Replace `SourceType.L5_DIGEST` → `SourceType.INFERRED`. L5 entities are
  LLM-extracted from L2 facts, so `INFERRED` is the correct semantic match.

- **`src/hyatlas_memory/l5_inprocess.py`** (`_embed_entities_to_qdrant`):  
  Replace hardcoded `:19528` HTTP call with in-process embedding via
  `patches._local_embed_model` (the same SentenceTransformer instance loaded by
  patch #3). Falls back to `MEMORY_L5_EMBED_URL` env var only if the in-process
  model is unavailable.

## Verification

After fix: awaiting next S2 digest to confirm entities land in Kuzu + Qdrant.

## Impacts

- **Critical** — L5 (knowledge graph), L6 (schema extraction), L7 (intention
  modeling) were completely non-functional in v2.0.0-rc despite all patches
  loading. This blocks the S-class memory promise.

- **Scope:** Affects any deployment running `MEMORY_L5_VERSION=2` after
  `apply_inprocess_embed_patch` landed (the combination that ships in v2.0.0).

## Notes

- The enum mismatch suggests `l5_inprocess.py` was developed against an
  unreleased or forked version of `hy_memory` that added `L5_DIGEST` to the
  `SourceType` enum. The current installed SDK does not have it.

- The `:19528` embedder sidecar existed in early HyAtlas Memory versions but was
  eliminated by patch #3 (in-process embedding). `l5_inprocess.py` was not
  updated to match that architectural change.

- This fix preserves the legacy `:19528` fallback path (gated by
  `MEMORY_L5_EMBED_URL` env var) for deployments that still run the sidecar, but
  the default behavior now uses the in-process model.
