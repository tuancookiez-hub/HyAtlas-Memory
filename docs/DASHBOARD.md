# HyAtlas Dashboard

> The local web UI for inspecting your memory atlas. Runs on `http://127.0.0.1:8765` and talks to the HyAtlas memory server on port 19527.

The dashboard is a single-page app served by `server/dashboard/dashboard.py` (a `BaseHTTPRequestHandler` with no external web-framework dependencies). The frontend is `server/dashboard/dashboard.html` — one self-contained file with HTML, CSS, and JavaScript that uses Three.js (CDN) for the 3D Observatory view.

## Quick start

```bash
# Auto-started by the plugin on first message, or start manually:
python -m server.dashboard.dashboard

# Or directly:
python server/dashboard/dashboard.py

# Open in browser:
open http://127.0.0.1:8765   # macOS
xdg-open http://127.0.0.1:8765 # Linux
start http://127.0.0.1:8765    # Windows
```

The dashboard reads the same config as the plugin (`~/.hyatlas/config/hy_memory.json` for upstream URL, `HERMES_USER_IDS` for which user scopes to query).

## Pages

The left sidebar has 6 pages. The currently active page is highlighted in gold.

| Page | Route | What it shows |
|---|---|---|
| **Overview** | `#overview` | KPI cards, memory composition bar chart, recent ingestion feed |
| **Memory Observatory** | `#observatory` | 3D galaxy visualization of all memory layers |
| **Explore Memory** | `#explore` | Searchable list of all memories with filters |
| **Memory Layers** | `#layers` | Table of all 8 layers with counts, percentages, and hierarchy |
| **Today / Activity** | `#today` | Digest of memories from the last 24 hours |
| **Settings / System** | `#system` | Storage stats, configuration, system info |

## Overview

The landing page after data loads. Shows at a glance:

- **KPI cards** — total memories stored, total cross-layer links, layer coverage (X/8)
- **Memory Composition** — horizontal stacked bar chart with percentage breakdown per layer (L0–L7)
- **Recent Ingestion** — live feed of the last 10 ingested memories, tagged by layer and timestamp
- **Memory Insight** — a one-line summary of the most active layer and total counts

**Auto-refresh:** every 5 seconds (configurable via `REFRESH_S` in `dashboard.py`). The page fades smoothly between refreshes.

## Memory Observatory

The flagship page — a 3D galaxy where each of the 8 memory layers is a horizontal "orbital band" of glowing nodes. Built on Three.js.

### Controls

| Filter | Effect |
|---|---|
| **Last 25 / 50 / 100 / 500** | How many of the most recent memories to plot as nodes |
| **Reset** | Re-fit the camera to show the full galaxy |
| **ALL** (layer filter) | Show all 8 layers |
| **L0 – L7** | Isolate a single layer |

### Camera

- **Scroll wheel** — zoom in/out
- **Click + drag** — pan
- **0** key — reset to fit
- **+ / −** keys — zoom in/out
- **Click a node** — focus on it, see details in the right panel, show connected nodes

### Animations

- **Entrance** — on first load, nodes start at the center and fly outward to their galaxy positions over 900ms (cubic ease-out)
- **Scope morph** — when switching between Last 25/50/100/500, nodes morph from old positions to new positions over 600ms
- **Layer filter** — non-selected layers dim to 10% opacity; selected layer stays at 100%

### Edge rendering

- **Cross-layer edges** — warm gold color (`#9a8d70`), 0.16 opacity
- **Same-layer edges** — neutral gray (`#77736b`), 0.09 opacity
- Edges are generated by keyword-overlap scoring + structural neighbors. At scope 500 you'll see ~180 edges total (~90 cross-layer, ~90 same-layer).

### Layer ordering (top to bottom)

```
L7  META PRINCIPLES    (outermost ring, largest radius)
L6  SCHEMAS
L5  KNOWLEDGE
L4  IDENTITY
L3  SUMMARIES
L2  FACTS              (densest layer)
L1  RAW
L0  BASIC INFO         (innermost ring, smallest radius)
```

Layer Y-spacing is 95px, centered around y=0.

## Explore Memory

A filterable, searchable list of all memories across all layers.

- **Search bar** — full-text search across memory content
- **Layer filter tabs** — filter by layer (L0–L7, coding, or ALL)
- **Source filter** — VDB / CODING / L1_RAW
- **Sort** — by timestamp, relevance, or confidence
- **Click a row** — expand to see full content, ID, metadata

- **Count** — how many memories in that layer
- **% of total** — proportion of overall memory
- **Tags** — any tags applied to memories in that layer

## Settings / System

Configuration and diagnostics:

- **Storage** — VDB provider, collection name, point count, embedding dimensions, file sizes
- **Configuration** — current `HERMES_USER_IDS`, upstream URL, model names
- **System info** — Python version, vector store provider (Zvec / legacy Qdrant), Kuzu version

## API endpoints

The dashboard's HTTP server (`server/dashboard/dashboard.py`) exposes these endpoints. All return JSON unless noted.

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/` | Serve `dashboard.html` |
| `GET` | `/assets/{path}` | Static assets (icons, images) with path-traversal guard |
| `GET` | `/api/memories?offset=0&limit=25` | Paginated memory list (deduped across user scopes, L1_RAW included) |
| `GET` | `/api/memories?offset=0&limit=500` | Max 500 items |
| `GET` | `/api/metrics?minutes=60` | Memory activity metrics |
| `GET` | `/api/status` | Hy-Memory upstream server status (VDB points, provider, collection) |
| `GET` | `/api/info` | Hy-Memory upstream server info |
| `GET` | `/api/storage` | VDB stats + on-disk file sizes (`vector_db/`, `cache.db`, `kuzu_db/`) |
| `GET` | `/api/health` | Dashboard health check (returns `{status: "ok", upstream: "..."}`) |
| `GET` | `/api/coding-memories?limit=25` | Coding-session memories (from `server/bin/l5_*` pipeline output) |
| `GET` | `/api/coding-count` | Total coding memory count |
| `GET` | `/api/layer-counts` | Counts per layer (L0–L4 from VDB) |
| `GET` | `/api/graph-counts` | Counts for L5/L6/L7 (from Kuzu graph) |
| `GET` | `/api/layer-health` | Hermes digest readiness: VDB + graph counts, fresh L2, digest log status |
| `GET` | `/api/l6-schemas?n=8&q=` | Sample L6 behavioral schemas from graph (`layer=l6_schema`) |
| `GET` | `/api/l5/graph` | Full L5 knowledge graph (nodes + relations). v2.0.0+ reads live from the server's `/api/v1/graph` (Patch 23); falls back to `l5_kuzu_export.json` only if the upstream is down. |
| `GET` | `/api/l5/context?memory_id=...` | Context for a specific memory. Same live-first / fallback pattern as `/api/l5/graph`. |
| `POST` | `/api/search` | Body: `{query, user_id, top_k, ...}` — passthrough to `/api/v1/search` |

### Query parameters

- **`offset`** — pagination offset (default 0)
- **`limit`** — max items to return (capped at 500 for `/api/memories`, 25 default)
- **`minutes`** — time window for metrics (default 60)
- **`memory_id`** — specific memory for L5 context

### Response shapes

Most endpoints return JSON with at least:
```json
{
  "memories": [...],
  "total": 1234,
  "offset": 0,
  "limit": 25
}
```

For full schemas, see the `if path ==` branches in `server/dashboard/dashboard.py` (`do_GET` method).

## Troubleshooting

### Dashboard won't load

```bash
# Check if the process is running
ps aux | grep dashboard.py

# Check what's bound to 8765
netstat -an | grep 8765    # macOS/Linux
netstat -ano | findstr 8765  # Windows

# Start manually to see errors
python server/dashboard/dashboard.py
```

### "500 Internal Server Error" on API calls

The upstream Hy-Memory SDK server (port 19527) is likely down. Restart it:
```bash
python -m server.start_server
```

Or check the plugin's subprocess logs.

### Observatory shows empty galaxy

1. Check the `OBS_LAYER_ORDER` in `dashboard.html` matches your data
2. Verify `/api/layer-counts` returns non-zero values
3. Try a smaller scope (Last 25) — large scopes can timeout during edge computation

### Boot screen won't fade

The `boot-screen` element is removed by `hideBootScreen()` after `loadAllData()` resolves. If it's stuck:
- Open browser console — check for fetch errors
- Verify `HERMES_USER_IDS` env var is set (comma-separated list of user IDs)

## Development

### Editing the frontend

The frontend is a single file: `server/dashboard/dashboard.html`. After editing, **hard-refresh** your browser (Ctrl+Shift+R) — the server serves with `Cache-Control: no-store` but the browser may cache aggressively.

### Adding a new API endpoint

1. Add a new `if path == "/api/your-endpoint":` branch in `do_GET` (or `do_POST`)
2. Use `self._json(status, payload)` to send JSON responses
3. The frontend can then `fetch('/api/your-endpoint')`

### Adding a new page

1. Add a `<div class="page-section" id="page-yourpage">...</div>` in the HTML body
2. Add a nav item in the sidebar: `<div class="nav-item" data-page="yourpage">...</div>`
3. Add a `renderYourPage()` function called from `renderAll()`

### Live iteration

```bash
# Run dashboard in foreground to see requests
python server/dashboard/dashboard.py

# In another terminal, tail the logs
tail -f server/dashboard/logs/dashboard.log
```
